## โมเดลที่ล็อก (รอบที่ 3–4 — `results/lock_decision.md`, `configs/rules.yaml → live`)

- **ทิศทาง:** E12 `fd_lr` (F0 + F-daily, Logistic สเปก E9-LR)
- **ราคาจุด:** กฎค่ามัธยฐาน (A-price LR + p_price) = P(c) ± 1 ช่อง หรือ P(c)
- **ช่วงราคา:** quantile ของ z (E0) รอบราคาจุด
- **P(c):** รอบเช้า = ราคาปิดทางการรวม ATC ของวันทำการก่อน (Settrade 1d → `05` ดึงให้เอง)
  — ตั้งแต่รอบที่ 4 โมเดลราคา / fl_* / z ฝึกด้วยนิยามเดียวกันนี้ (`label.p_ref_morning: official_close`)
  · รอบบ่าย = ราคาซื้อขายล่าสุดจากแท่ง 1m ณ จุดตัด (`reference_source` บอกแหล่ง)
- **รันเงา:** E0-ud + ราคาล่าสุด ณ จุดตัด → `outputs/logs/shadow_log.jsonl` (**ห้ามส่ง** ห้ามใช้เปลี่ยนโมเดล)
- **ซ้อมกับสำเนาข้อมูล** (`--data-root <โฟลเดอร์ที่มี settrade/ yfinance/> --no-fetch --now ...`): เช่น T3 ที่ลบแถวรายวันของเมื่อวาน
- **ซ้อม / ทดสอบย้อนหลัง** (`--now`): log ไปที่ `outputs/logs/dryrun/` และไฟล์ส่งผลไปที่ `outputs/predictions/dryrun/` ไม่ปนกับของจริง
- **Refit ศ. 6 พ.ย.:** `python scripts/04_lock_model.py` ครั้งเดียว (ล็อกทุกโมเดลใน `live`) — ห้ามเปลี่ยนโมเดลระหว่าง 9–13 พ.ย.
— actuals ถูกเพิ่มภายหลังโดย `06_score_live.py` ในไฟล์แยก (`outputs/reports/live_scored.csv`)

## แผนสำรอง

| ปัญหา | ระบบทำอะไร | คนทำอะไร |
|---|---|---|
| ข้อมูลวันนี้ไม่ทัน (ไม่มีแท่ง 1m จากทุกแหล่ง) | **ยังรันโมเดลที่ล็อก** ด้วย features จากข้อมูลล่าสุดที่ผ่านเกณฑ์ + ระบุอายุข้อมูล (`data_age_min`) ใน `fallback_reason` | ส่งตามไฟล์ |
| แท่งรายวัน (Settrade 1d) / 60m ของวันทำการก่อนยังไม่มา | ไล่ขั้น (`live/daily_check.py`): 2 ดึงซ้ำ → 3 สร้างจาก Settrade 1m / yfinance 1d ลงสำเนา `outputs/live_cache/` (ไม่แก้ `data/raw`) → 4 วนดึงซ้ำถึงเส้นตาย − 5 นาที แล้วส่งด้วยข้อมูลล่าสุดที่มี · กรอบ `!!!!` + `fallback_reason` บอกขั้น | ส่งตามไฟล์ ตรวจ `00_collect_daily.py` ของเมื่อวาน |
| ไฟล์โมเดล / features ใช้ไม่ได้ | ทางสุดท้าย: **E0-ud** จากประวัติ + ธง `fallback_reason` | ส่งตามไฟล์ แล้วดูสาเหตุหลังส่ง |
| โมเดลราคาล้ม | ราคาจุด = P(c) + ธง | ส่งตามไฟล์ |
| ราคาอ้างอิงรอบบ่ายเก่าเกิน `max_price_age_min` | ทำนายต่อแต่ติดธง | ตรวจว่าไฟล์รายนาทีอัปเดตหรือไม่ |
| Settrade (แหล่งหลัก) ไม่มีข้อมูล / ค้างเกิน `live.max_bar_lag_min` | ใช้ yfinance 1m แทน (บันทึก `data_source` ใน log) — yfinance มักช้า 15–20 นาที จึงมักถูกข้ามด้วย → ใช้ข้อมูลล่าสุดที่ผ่านเกณฑ์ | ตรวจว่าแหล่งไหนถูกใช้ |
| ทุกแหล่งล้มและโมเดลรันไม่ได้ | E0-ud + ธง `fallback_reason` | กรอกมือได้ **เฉพาะก่อนส่ง** พร้อมแหล่งและเวลา |
