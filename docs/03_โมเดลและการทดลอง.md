> แผนหัวข้อ 06–10 · โค้ด: `src/forecast/models/` · ตั้งค่าการทดลอง: [`experiments.yaml`](../configs/experiments.yaml)

## โมเดล

| แบบ | โครงสร้าง | หน้าที่ | ไฟล์ | รหัสเดิม |
|---|---|---|---|---|
| **A: Baseline** | ราคา = ราคาล่าสุดที่รู้; ทิศทาง = ความถี่ในอดีต | เกณฑ์ขั้นต่ำ | `baseline.py` | แบบ A |
| **B: อิสระ** | Logistic ทิศทาง + quantile GBM ราคา | ฐานเทียบว่าการเชื่อมช่วยไหม | `independent.py` | M1–M4, M6, แบบ B |
| **C: สองขั้น** | probability แบบ temporal OOF + features → ราคา | **คำถามวิจัยหลัก** | `cascade.py` | M5, แบบ C |
| **D: ส่วนเพิ่ม** | 1D-CNN / เวลา–ความถี่ | คู่แข่งเมื่อฐานพร้อม | `cnn1d.py`, `features/spectral.py` | C1, C2, C8, M7 |

## โมเดลสองขั้น (Cascade) — กันการรั่ว

```
ขั้น 1: ข้อมูลที่รู้ก่อนส่ง → probability ทิศทาง
ขั้น 2: features เดิม + probability ที่สร้างโดยไม่เห็นอนาคต → z และ quantiles ราคา
```

1. outer folds ตามเวลา (walk-forward)
2. ภายในอดีตของ outer fold แบ่งเป็นบล็อกเวลา → บล็อก i ได้ probability จากโมเดลที่ฝึกบนบล็อก < i
3. calibrator (ถ้าเปิด `calibrate`) fit จาก OOF ในอดีตเท่านั้น
4. ขั้นสองฝึกบนแถวที่มี OOF จริง (บล็อกแรกถูกตัด)
5. outer test: ขั้นหนึ่งฝึกบนอดีตทั้งหมด → ขั้นสอง

❌ ห้ามใช้ probability จากข้อมูลที่ขั้นหนึ่งเคยฝึก · ❌ ห้ามใช้ OOF แบบสุ่ม

## ช่วงราคา

- Q10 / Q25 / Q50 / Q75 / Q90 → ค่ากลาง, ช่วง 50%, ช่วง 80%
- แก้ quantile crossing ด้วยการเรียงค่า (`models/common.py`)
- ไม่บังคับให้ราคาคาดการณ์อยู่ฝั่งเดียวกับทิศทาง เพราะราคาเริ่มต้นจริงยังไม่รู้ตอนส่ง

## CNN และเวลา–ความถี่

| การทดลอง | ข้อมูลเข้า | ลำดับ | รหัส |
|---|---|---|---|
| 1D-CNN รอบบ่าย | แท่งวันนี้ถึงจุดตัด: signed r, \|r\|, volume | **เริ่มก่อน** | C1 |
| 1D-CNN รอบเช้า | แท่งวันก่อน | ถัดไป | C2 |
| ตัวแปรความถี่ | band power + features เดิม | ก่อนภาพ CNN | C8 (ย่อ) |
| Spectrogram-CNN | ภาพเวลา–ความถี่ + ลำดับ + บริบท | เมื่อฐานพร้อม | C8 |
| 2D / GAF / transfer | — | พักไว้ | C3–C7 |

- CNN เล็ก 2 ชั้น + dropout + weight decay + early stopping บน validation ที่อยู่ **หลัง** train
- หลาย seed ตามที่กำหนดก่อน แล้วเฉลี่ย — ไม่เลือก seed ดีที่สุด
- power ของ r กับ −r เท่ากัน → ต้องใช้คู่กับ signed returns เสมอ
- Welch / spectrum เป็น EDA ประกอบ ไม่ใช่ตัวตัดสินความละเอียด; Grad-CAM / SHAP ไม่ใช่หลักฐานเหตุและผล
