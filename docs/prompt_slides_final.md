### กติกาการอ้างนัยสำคัญทางสถิติ (หมายเหตุ 1)
ทุกครั้งที่สไลด์กล่าวว่า "มีนัยสำคัญ" หรือ "ไม่มีนัยสำคัญ" ต้องแสดง **ทั้งผลและวิธี** บนสไลด์เดียวกัน หรืออ้างถึงสไลด์วิธีการที่ระบุชัด ได้แก่:
1. ค่าที่เปรียบเทียบ (เช่น ความแม่นยำของโมเดล − ความแม่นยำของตัวเทียบ)
2. ช่วงความเชื่อมั่น (CI) พร้อมระดับ (95%, 98.75%, 99.7%)
3. วิธีคำนวณ: block bootstrap รายวัน 2,000 ครั้ง และการปรับ Bonferroni ถ้ามีหลายการเทียบ
4. เกณฑ์ตัดสิน: "มีนัยสำคัญเมื่อ CI ไม่ครอบศูนย์"
5. จำนวนตัวอย่างที่ใช้ (n)

ให้มีสไลด์ "วิธีทดสอบนัยสำคัญ" หนึ่งหน้าในส่วน Methodology ที่อธิบายข้อ 1–5 แล้วสไลด์ผลลัพธ์อ้างถึงได้

## 1. Problem Statement (ที่มาและปัญหา) — 3–4 สไลด์

- ตารางโจทย์ (ตรวจกับ `configs/rules.yaml` และ `docs/01_โจทย์และกติกา.md`):

### 1.2 ลักษณะของปัญหาที่ทำให้ยาก
ใส่เฉพาะสิ่งที่งานนี้ **แก้หรือรับมือจริง** และโยงไปยังสไลด์ Methodology ที่แก้:
- ราคาระหว่างวันใกล้เคียงการเดินสุ่ม (random walk) ตามทฤษฎีตลาดมีประสิทธิภาพ (Fama, 1970) สัญญาณที่ทายได้จึงอ่อน → รับมือด้วยการทดสอบนัยสำคัญที่เข้มงวด
- ราคาขยับเป็นช่องราคา (tick) ทำให้มีวันที่ราคาเท่าเดิม 16–28% ของรอบ → โมเดลวันนิ่งและเป้าหมายขึ้น/ไม่ขึ้น
- ข้อมูลระหว่างวันย้อนหลังมีจำกัด → ใช้แท่ง 60 นาที 730 วัน
- ต้องส่งก่อนตลาดเปิด/ระหว่างพัก → การกำหนดจุดตัดข้อมูลและระบบอัตโนมัติ

## 2. Objective (วัตถุประสงค์) — 1 สไลด์

เขียนเป็นข้อที่วัดผลได้ เช่น:
1. พัฒนาโมเดลพยากรณ์ทิศทาง (ขึ้น/ไม่ขึ้น) ของ KBANK และ ADVANC ทั้งสองรอบ ที่มีความแม่นยำเหนือตัวเทียบทางสถิติอย่างมีนัยสำคัญ ภายใต้การทดสอบแบบเดินหน้า
2. พัฒนาโมเดลพยากรณ์ราคาและช่วงราคา ที่มีความคลาดเคลื่อน (RMSE) ไม่สูงกว่าการใช้ราคาล่าสุด และมีช่วงราคาที่ครอบคลุมราคาจริงตามระดับที่กำหนด
3. ประเมินว่าข้อมูลความละเอียดสูง (5 นาที/1 นาที) และภาพ scalogram กับ CNN ที่ฝึกล่วงหน้า (pretrained) ช่วยการพยากรณ์ได้หรือไม่
4. สร้างระบบส่งผลอัตโนมัติที่ทำงานได้จริงบนเครื่องคลาวด์ ตลอดสัปดาห์ส่งจริง
5. ประเมินมูลค่าทางการเงินของโมเดลด้วย XIRR และ Sharpe ratio

## 5. Methodology (วิธีดำเนินการ) — 8–12 สไลด์

### 5.1 ภาพรวมกระบวนการ
แผนภาพ: เก็บข้อมูล → สร้าง feature ณ จุดตัด → โมเดลทิศทาง + โมเดลราคา → ทดสอบแบบเดินหน้า → ทดสอบนัยสำคัญ → เลือกโมเดลตามเกณฑ์ที่ลงทะเบียนล่วงหน้า → ระบบส่งอัตโนมัติ

### 5.2 Feature (หมายเหตุ 2)
**ทุก feature ต้องมี 3 คอลัมน์: ชื่อ | วิธีคิด (สูตร) | ช่วยอะไร** แบ่งหมวดตามด้านล่าง ตรวจรายชื่อและสูตรจริงจากโค้ดและ `configs/feature_dictionary.csv` ถ้าหมวดใดมีหลายตัว ทำสไลด์ละหมวด และระบุว่าใช้ในรอบเช้า บ่าย หรือทั้งสอง

**หมวด 1: ผลตอบแทนและความผันผวนจากราคาระหว่างวัน (F0; เช้า 6 ตัว บ่าย 9 ตัว)**
ตัวอย่างที่ต้องมี (ตรวจชื่อจริง):
- ผลตอบแทน 1 วันและ 5 วัน: `ln(Close_t / Close_{t−k})` → จับโมเมนตัมและการกลับตัวระยะสั้น
- ผลตอบแทนเฉลี่ยของรอบเดียวกัน 5/20 วัน → จับแนวโน้มเฉพาะช่วงเวลาของวัน
- ผลตอบแทนรอบบ่ายเมื่อวาน → ความต่อเนื่องระหว่างรอบ
- ความผันผวน 5 วัน: ส่วนเบี่ยงเบนมาตรฐานของผลตอบแทน → ปรับความมั่นใจตามความเสี่ยง
- (บ่าย) ผลตอบแทนตั้งแต่เปิดถึงจุดตัด, gap ราคาเปิด, ความผันผวนภาคเช้า → ข้อมูลของวันนั้นก่อนส่ง
- ตัวแปรร่วม ผลตอบแทนภาคเช้า × ความผันผวน (ถ้าอยู่ในโมเดลที่ใช้)

**หมวด 2: ตัวชี้วัดทางเทคนิครายวัน (F-daily; 24 ตัว)**
- ผลตอบแทน 1/2/3/5/10 วัน
- ช่วงสูง–ต่ำ: `(High − Low) / Close` → ความผันผวนภายในวัน
- เปิด→ปิด: `ln(Close / Open)` → แรงซื้อขายระหว่างวัน
- **ตำแหน่งราคาปิดในกรอบวัน: `(Close − Low) / (High − Low)`** → feature สำคัญที่สุด จับการกลับตัวหลังปิดใกล้จุดสูง/ต่ำ
- `Close/SMA5`, `Close/SMA20`, `Close/EMA5`, `Close/EMA20`, `SMA5/SMA20` → ระยะห่างจากค่าเฉลี่ย แนวโน้มสั้น/กลาง
- RSI 14 วัน: `100 − 100/(1 + RS)` โดย RS = ค่าเฉลี่ยขาขึ้น/ขาลง → ภาวะซื้อมาก/ขายมาก
- MACD: `EMA12 − EMA26` (และเส้นสัญญาณ) → โมเมนตัม
- ตำแหน่งและความกว้าง Bollinger: `(Close − SMA20)/(2σ20)`, `4σ20/SMA20` → ความผันผวนสัมพัทธ์
- ATR 14: ค่าเฉลี่ยของ True Range → ขนาดการขยับปกติ
- จำนวนวันขึ้นติดกัน → การกลับตัวหลังขึ้นต่อเนื่อง
- ระยะจากจุดสูง/ต่ำ 20 วัน → ตำแหน่งในกรอบระยะกลาง
- `Volume / SMA20(Volume)` → ความผิดปกติของปริมาณซื้อขาย

**หมวด 3: วันในสัปดาห์ (5 ตัว)** one-hot → ผลของวันในสัปดาห์

**หมวด 4: ตัวแปรบอกหุ้น** dummy → ให้โมเดลรวมสองหุ้นแยกค่าเฉลี่ยของแต่ละหุ้น

**หมวด 5: feature วันนิ่ง (ใช้ในโมเดลราคา/วันนิ่ง)**
- การขยับที่คาดเป็นจำนวนช่องราคา: `ATR / tick_size(P(c))` → โอกาสราคาเท่าเดิม
- ช่วงสูง–ต่ำรอบล่าสุดเป็นจำนวนช่อง
- สัดส่วนวันนิ่ง 20 วัน

**หมวด 6: ตัวชี้วัดทางเทคนิคบนแท่ง 60 นาที (F-60m; รอบบ่าย)** RSI, MACD, Bollinger, SMA20, ATR บนแท่ง 60 นาที

**หมวดที่ทดลองแต่ไม่ใช้ในโมเดลส่งจริง (สไลด์แยก ระบุผลสั้น ๆ):**
- ชั้น 2 จากแท่ง 5 นาที (E13): ผลตอบแทน 15 นาทีสุดท้าย, ราคาเทียบ TWAP, ตำแหน่งในกรอบภาคเช้า

ปิดหมวด feature ด้วยกราฟ **permutation importance** ของโมเดลที่ใช้จริง

### 5.3 Model ที่ใช้
- **ตัวเทียบ:** E0-ud (ทางที่เกิดบ่อยในวันที่ราคาขยับ), E0-un (ทาย "ไม่ขึ้น" ทุกรอบ), ราคาล่าสุด P(c)
- **โมเดลทิศทาง:**
  - **รอบเช้า: A-ud** = L2 logistic regression รวมสองหุ้น feature หมวด 1–4 เลือก C จาก {0.003, 0.01, 0.03, 0.1} ด้วย inner time-series CV และ bagging 20 รอบ (block 20 วัน) ฝึกแบบขึ้น/ลง
  - **รอบบ่าย: E15 MLP** = MLP ของ scikit-learn ที่จูนด้วย Optuna และเลือก feature ภายใน nested walk-forward ฝึกแบบขึ้น/ไม่ขึ้น (ตรวจสถาปัตยกรรมและพารามิเตอร์จริงจากไฟล์ล็อก)
- **โมเดลราคา PR-A:** A-price (P(ราคาปลาย = P(c))) + p_price (P(สูงกว่า | ไม่เท่า)) แล้วเลื่อน ±1 ช่องเมื่อความน่าจะเป็นเกิน 0.5 (กฎค่ามัธยฐาน) ช่วงราคา 50%/80% จาก quantile ในอดีต
- **โมเดลที่ทดลองแต่ไม่ได้ใช้ (สไลด์สรุป):** LightGBM, XGBoost, CatBoost, Random Forest, SVM, ElasticNet, ensemble, CNN (AlexNet, VGG16-BN, ResNet18, DenseNet121, Inception-v3) บนภาพ scalogram แท่ง 60m/5m/1m, pretrain → fine-tune (รวมเช้า-บ่าย, ยืมข้อมูล ADVANC), feature ต่างประเทศ
- **สไลด์ "ลำดับการพัฒนา" รอบ 1 → 7:** แต่ละรอบเปลี่ยนอะไร ผลดีที่สุด และบทเรียน

### 5.4 การทดสอบและการเลือกโมเดล

- **Nested walk-forward:** การเลือกพารามิเตอร์/feature/ตัวแทนใช้ข้อมูลฝึกเท่านั้น
- **การป้องกันข้อมูลรั่ว:** test อัตโนมัติ (truncation, perturbation), ตรวจ feature วันจริงเทียบ backtest (เช่น 38/38 ตัว, 1,044 ค่า)
- **การตรวจ overfit:** train gain เทียบ test gain, PBO/CSCV

### 6.1 ผลการทายทิศทาง (Classification)
สำหรับ **โมเดลที่ใช้จริงทุกช่อง** (A-ud เช้า, E15 MLP บ่าย) และตัวเทียบ E0-un แยกรอบ (และแยกหุ้นในภาคผนวก):

1. **Confusion matrix** ขนาด 2×2 (จริง ขึ้น/ไม่ขึ้น × ทาย ขึ้น/ไม่ขึ้น) ภายใต้กติกาให้คะแนนจริง (วันนิ่ง = ไม่ขึ้น) แสดงเป็นจำนวนและร้อยละ ทำเป็น heatmap
2. **ตัวชี้วัด** จาก confusion matrix:
   - Accuracy = (TP + TN) / N
   - **Precision** = TP / (TP + FP)
   - **Sensitivity (Recall)** = TP / (TP + FN)
   - **Specificity** = TN / (TN + FP)
   - F1, Balanced accuracy = (Sensitivity + Specificity) / 2
   - AUC และ log loss
   - ถ้าโมเดลแทบไม่ทาย "ขึ้น" (เช่น E15 MLP ทายขึ้น ~0.1%) Precision อาจหาค่าไม่ได้ (TP + FP = 0) ให้แสดงเป็น "ไม่นิยาม" พร้อมอธิบาย ห้ามใส่ 0 หรือ 100% แทน
3. **ตารางเทียบตัวเทียบพร้อมนัยสำคัญ** (ตามข้อ 0): ผลต่างความแม่นยำและ log loss กับ E0-un และ A-ud พร้อม CI
4. **การตีความ (ต้องมี):**
   - ความแม่นยำของรอบบ่าย (~65%) เกิดจากอัตรา "ไม่ขึ้น" ที่สูง ไม่ใช่การแยกวันขึ้นได้ ให้แสดง Sensitivity และ Balanced accuracy ประกอบ
   - ไม่มีโมเดลใดชนะ E0-un อย่างมีนัยสำคัญ (แสดงตาราง E16/E15/E14 พร้อม CI)
   - ผล A-ud บนเป้าหมายขึ้น/ลง (+4.4 จุด [CI]) เป็นหลักฐานว่ามีสัญญาณแยกทิศทางเมื่อราคาขยับ
5. **สไลด์ผลรวมการทดลองทั้งโครงการ:** ตารางสรุปทุกกลุ่มการทดลอง (รอบ 1–7, E0–E27) ผลดีที่สุด และผ่าน/ไม่ผ่าน พร้อม PBO

### 6.2 ผลการทำนายราคา (Regression)
- **RMSE เป็นตัวชี้วัดหลัก** (MAE เป็นตัวชี้วัดเสริม) แยกหุ้นและรอบ ของ PR-A, ราคาล่าสุด P(c), PR-mean และแบบที่ดีที่สุดของ E17
- ผลต่าง RMSE กับ P(c) พร้อม CI (bootstrap แบบคำนวณ RMSE ใหม่ทุกรอบ จับคู่วันเดียวกัน)
- Coverage ของช่วงราคา 50%/80% และความกว้างเฉลี่ย
- **ผลวิเคราะห์เพดาน (E27):** ถ้ารู้ราคาเปิดจริง RMSE รอบเช้าลดจาก ~3.08 เป็น ~2.50 บาท → ความคลาดเคลื่อนส่วนใหญ่มาจากการขยับหลังตลาดเปิด
- **ข้อจำกัด XD:** RMSE backtest รอบเช้าสูงกว่าระบบจริงราว 0.10 บาท เพราะไม่หักเงินปันผลวัน XD
- กราฟ: ราคาจริงเทียบราคาคาดและช่วงราคา (ตัวอย่าง 2–3 สัปดาห์) และ histogram ของความคลาดเคลื่อน

### 6.3 การประเมินทางการเงิน: XIRR และ Sharpe ratio
**ต้องสร้างใหม่ใน `experiments/61_financial_eval.py` และลงทะเบียนวิธีใน `results/financial_preregistration.md` ก่อนคำนวณ**

**กลยุทธ์ (ตามสัญญาณทิศทางของโมเดลที่ใช้จริง แยกรอบ):**
- **S1 Long-only (หลัก):** เมื่อโมเดลทาย "ขึ้น" ซื้อที่ราคาต้นรอบ (เช้า P(10:00), บ่าย P(14:00)) และขายที่ราคาปลายรอบ (เช้า P(12:30), บ่ายราคาปิดทางการ) เมื่อทาย "ไม่ขึ้น" ถือเงินสด
  - ใช้ได้จริงเพราะซื้อขายในวันเดียวกัน ไม่ต้องขายชอร์ต
- **S2 Long/Short (อ้างอิง):** ทาย "ขึ้น" ซื้อ ทาย "ไม่ขึ้น" ขายชอร์ต ระบุว่าเป็นกรณีทางทฤษฎี (การขายชอร์ตในตลาดไทยมีข้อจำกัด)
- **ตัวเทียบ:** B1 ซื้อทุกรอบ (always long), B2 ซื้อแล้วถือ (buy-and-hold ตลอดช่วง), B3 ถือเงินสด (E0-un ในทางปฏิบัติ)

**สมมติฐาน (เขียนบนสไลด์):**
- เงินลงทุนตั้งต้นต่อหุ้นต่อรอบคงที่ (เช่น 100,000 บาท) ไม่ทบต้นภายในวัน
- ค่าธรรมเนียม: รายงาน 2 กรณี (ก) ไม่มีค่าธรรมเนียม (ข) ค่าธรรมเนียมซื้อขายออนไลน์ประมาณ 0.157% ต่อขา (รวม VAT; ตรวจอัตราจริงของโบรกเกอร์และระบุแหล่ง)
- ไม่คิด slippage (ซื้อขายที่ราคาประมูลเปิด/ปิด) ระบุเป็นข้อจำกัด
- ไม่รวมเงินปันผล (ซื้อขายภายในวัน)

**ตัวชี้วัด:**
- **XIRR:** อัตราผลตอบแทนต่อปีจากกระแสเงินสดที่มีวันที่จริง (ออกเงินตอนซื้อ รับเงินตอนขาย) แก้สมการ Σ CFᵢ / (1 + r)^((dᵢ − d₀)/365) = 0 ด้วยวิธีเชิงตัวเลข (เช่น `scipy.optimize.brentq`) และตรวจผลกับฟังก์ชัน XIRR ของ Excel อย่างน้อย 1 กรณี
- **Sharpe ratio (รายปี):** (ค่าเฉลี่ยผลตอบแทนรายวัน − อัตราปลอดความเสี่ยงรายวัน) / ส่วนเบี่ยงเบนมาตรฐานรายวัน × √252 ใช้ผลตอบแทนรายวันของพอร์ต (รวมทั้งสองหุ้น วันที่ไม่ลงทุน = 0) อัตราปลอดความเสี่ยง: ระบุค่าและแหล่ง (เช่น ผลตอบแทนพันธบัตรรัฐบาลไทยอายุ 1 ปี หรืออัตรานโยบาย ธปท.) และรายงานกรณี rf = 0 คู่กัน
- เสริม: ผลตอบแทนสะสม, max drawdown, จำนวนครั้งที่ซื้อขาย, อัตราชนะ (win rate)
- **ช่วงความเชื่อมั่นของ Sharpe ratio** ด้วย block bootstrap รายวัน 2,000 ครั้ง และผลต่าง Sharpe ระหว่างกลยุทธ์โมเดลกับ B1 (เพื่อใช้กติกานัยสำคัญตามข้อ 0)

**รายงาน:** ช่วง walk-forward, holdout และส่งจริง (ถ้ามี) แยกรอบและรวม พร้อมกราฟ equity curve ของ S1 เทียบ B1 และ B2

**การตีความที่ต้องมี:**
- รอบบ่าย E15 MLP แทบไม่ทาย "ขึ้น" จึงแทบไม่ซื้อขาย XIRR/Sharpe จะใกล้ศูนย์ (ถือเงินสด) ให้อธิบายตรง ๆ
- ความแม่นยำสูงไม่ได้แปลว่ากำไรสูง ต้องดูขนาดของการขยับในวันที่ทายถูก/ผิดด้วย
- ผลทางการเงินเป็นการจำลองย้อนหลัง ไม่ใช่คำแนะนำการลงทุน
